## 📌 Огляд архітектури та можливостей

Програмний брандмауер функціонує в просторі користувача як мережевий проксі-сервіс (TCP/UDP) з механізмом фільтрації з'єднань у реальному часі та REST Admin API:

1. **Фільтрація за багатокритеріальними правилами:**
   - IP-адреси або підмережі джерела (`src`) та призначення (`dst`) з підтримкою нотації CIDR (наприклад, `26.147.33.0/24`).
   - Порти джерела (`src_port`) та призначення (`dst_port`).
   - Протоколи: `TCP`, `UDP`, `ANY`.
   - Дії: `ALLOW` (пропустити) або `DENY` (скинути/заблокувати з'єднання).
   - Пріоритети правил (`priority`): детерміноване вирішення конфліктів у зонах перекриття.

2. **Динамічне керування без перезавантаження (Admin API & fwctl):**
   - Вбудований HTTP Admin API (`127.0.0.1:8081`).
   - Консольна утиліта `fwctl.py` для перегляду (`list`), додавання (`add`), вмикання (`enable`), вимикання (`disable`), видалення (`delete`) правил та аналізу конфліктів (`conflicts`).
   - Усі зміни правил застосовуються миттєво до наступного вхідного з'єднання.

3. **Аналіз конфліктів, дублікатів та перекриттів:**
   - **Дублікати:** однаковий набір умов та однакова дія $\rightarrow$ відхилення з кодом HTTP 409 (`duplicate_rule`).
   - **Прямі конфлікти:** однакові умови, протилежні дії, однаковий пріоритет $\rightarrow$ відхилення з кодом HTTP 409 (`conflict_same_priority`).
   - **Перекриття з однаковим пріоритетом:** часткове перекриття діапазонів IP за однакового пріоритету $\rightarrow$ відхилення (`overlap_same_priority`).
   - **Перекриття з різними пріоритетами:** дозволяється з видачею попередження, порядок виконання однозначно визначається пріоритетом.

4. **Журналювання аудиту безпеки (Audit Logging):**
   - Структурований формат JSON Lines (`logs/firewall.jsonl`).
   - Фіксація мережевих подій (`tcp.connect`, `udp.packet`) та адміністративних змін (`admin.rule_add`, `admin.rule_update`, `admin.rule_delete`, `admin.rule_rejected`).
   - Утиліта аналізу `analyze_logs.py` з підтримкою зведеної статистики та фільтрації за критеріями (`--src`, `--dst`, `--proto`, `--action`, `--reason`, `--event`).

## 🚀 Встановлення та запуск

### 1. Запуск служби брандмауера
```bash
python firewall.py --config config.json
```
*Служба активує Admin API на `127.0.0.1:8081` та TCP-проксі на `0.0.0.0:8080` з перенаправленням на `example.org:80`.*

## 🛠 Керування правилами через `fwctl.py`

### Перегляд поточної таблиці правил:
```bash
python fwctl.py list
```

### Додавання правил фільтрації:
```bash
# Блокування клієнта за IP-адресою:
python fwctl.py add --action deny --proto TCP --src 26.147.33.195 --reason "блокування тестового клієнта"

# Блокування за цільовим портом 80:
python fwctl.py add --action deny --proto TCP --dst-port 80 --reason "блокування порт 80"

# Блокування UDP-трафіку:
python fwctl.py add --action deny --proto UDP --src 26.147.33.195 --reason "блокування UDP трафіку"

# Дозвіл для підмережі з вищим пріоритетом (prio=20):
python fwctl.py add --action allow --proto TCP --src 26.147.33.0/24 --priority 20 --reason "дозвіл підмережі"
```

### Динамічна зміна стану та видалення:
```bash
# Тимчасово вимкнути правило #1:
python fwctl.py disable 1

# Увімкнути правило #1:
python fwctl.py enable 1

# Видалити правило #1:
python fwctl.py delete 1
```

### Перевірка конфліктів та зон перекриття:
```bash
python fwctl.py conflicts
```

## 📊 Аналіз та пошук у журналах (`analyze_logs.py`)

```bash
# Загальна зведена статистика:
python analyze_logs.py

# Останні 5 записів:
python analyze_logs.py --last 5

# Пошук заблокованих з'єднань від конкретного хоста:
python analyze_logs.py --src 26.147.33.195 --proto TCP --action deny

# Пошук за ключовим словом у причині блокування:
python analyze_logs.py --reason блок

# Аудит дій адміністратора з конфігурацією:
python analyze_logs.py --event admin
```
